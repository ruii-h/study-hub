3 · Searching & sorting
  • Linear search O(n), any list. Binary search O(log n), sorted only, mid = (lo+hi)//2, ≤ ⌊log₂n⌋+1 comparisons (n=1000 → ≈10; doubling n adds 1).
  • Insertion sort: insert the next item into the sorted left part. best O(n) (sorted), worst O(n²) (reversed). Swaps = #inversions; a failing compare still counts.
  • Selection sort always O(n²): n(n−1)/2 compares, ≤ n−1 swaps. After k passes the first k are final.
  • Merge sort: log₂n levels × n work = O(n log n), best = worst, extra O(n) space. Merging sizes a, b: at most a+b−1 compares. Recursive: sort LEFT fully, then RIGHT, then merge (calls finish in post-order).
def merge_sort(a):
  if len(a)<=1: return a
  mid=len(a)//2
  L=merge_sort(a[:mid]); R=merge_sort(a[mid:])

  return out+L[i:]+R[j:]

6 · Trees & BSTs
  • Root, leaf, parent/child, ancestor/descendant, siblings. Level: root = 1. Height = max level (empty = 0). n nodes → n−1 edges.
  • Full: every node has 0 or 2 children. Complete: all levels full except the last, packed left. Perfect: all leaves at the same depth, 2h−1 nodes. Balanced: subtree heights differ by ≤ 1.
  • Preorder P L R (first = root) · Inorder L P R (sorted on a BST) · Postorder L R P (last = root). All O(n).
  • BST: left < node < right. Search/insert: walk, O(height); insert goes where the search failed.
  • Delete: leaf → cut · one child → parent adopts it · two children → replace with the successor (leftmost of the right subtree) or predecessor (rightmost of the left).
  • Balanced O(log n); sorted insertion order → a chain, O(n). Height formulas: n nodes → height between ⌈log₂(n+1)⌉ (min, = ⌊log₂n⌋+1) and n (chain). Perfect tree of height h: 2h−1 nodes, 2h−1 leaves; max nodes at level L = 2L−1. Full: leaves = internal+1. height(node) = 0 if None else 1+max(hL,hR).
  • Level order (breadth first) uses a queue. Rebuild a tree from preorder + inorder: first preorder item = root, split the inorder list around it.

Topological ordering

  • Lists every vertex so for every edge u→v, u comes first. Exists iff the graph is a DAG; not unique; the first vertex has in-degree 0.
  • DFS method: push each vertex when its call finishes; reverse the finish order (pop the stack).
  • Visit sequence ≠ topological order; don’t forget to reverse. DAG A:[B,C] B:[C,D,E] C:[D] D:[F] E:[D] F:[] → A B E C D F (or A B C E D F).
  • 9-vertex example (alphabetical lists): visit A B G F E I C D H; finish G B E I F A H D C; topological C D H A F I E B G.
10 · Graph search & uniform cost search
  • Model: states, legal moves, goal state; ignore invalid and repeated states. Fewest edges ≠ lowest weight: add up the weights.
  • UCS = BFS with a priority queue ordered by total cost so far. Entries vertex(cost, from). Needs non-negative weights; it is Dijkstra stopped at the target.

  • Stop when the target is DEQUEUED, not when it is first enqueued. Path = follow the “from” links back.

  • Pick two of general / optimal / fast. Heuristics = fast + general, not guaranteed optimal.

  • Nearest neighbour (greedy construction): go to the closest unvisited city, finally home. n−1 steps × scan n = O(n²). Looks one step ahead only, so the forced last leg can be long. State tie-breaks; count the return leg.
  • Cheapest-side insertion: start with the closest pair; repeat: take the outside city x closest to a tour city y, insert x on the side of y that adds less: Δ = d(n,x) + d(x,y) − d(n,y) (check both sides). O(n³). Example Δ = 11+10−6 = 15. The two methods may disagree.
  • Local search: start from a complete solution, repeat small improving changes until a local optimum. Can stop any time; can be stuck below the global optimum; a bad start needs many steps.
  • 2-opt: delete 2 edges, reconnect (= reverse a segment). Δ = new legs − old legs, keep it if Δ < 0 (e.g. 13+13 − 12−28 = −14). Neighbours = n(n−3)/2 = O(n²). Removes crossings.
  • Hill climbing (grid): move to the highest neighbour, stop when none is higher. Random start, ends at a local peak; a heuristic, not brute force, no global guarantee.

12 · Limits of computationHIGH WEIGHT
  • Efficient = polynomial time; tractable = a polynomial algorithm is known. 2ⁿ and n! are hopeless even for small n: 20! ≈ 2.4×10¹⁸ steps (~77 years).
  • P: can be solved in polynomial time. NP: a proposed answer can be verified in polynomial time (subset sum: just add them up). P ⊆ NP. NP ≠ “not polynomial”.
ClassMeaningHow you show it
Pfast to solvegive a fast algorithm
NPfast to checkgive a fast checker
NP-completein NP + hardest in NPin NP, and reduce a known NP-complete problem to it

Reduction A → B: convert any A-instance into a B-instance fast, so a B-solver also solves A. B is at least as hard as A (arrow: easier → harder). E.g. subtraction → addition (A−B = A+(−B)); sorting → topological sort; Hamiltonian cycle → TSP (distance 1 if an edge exists, else 2; ask for a tour ≤ n).
NP-complete = (1) in NP and (2) every problem in NP reduces to it (the hardest in NP). Ex: subset sum, SAT, Hamiltonian cycle, TSP (decision). NP-hard = (2) only; may not be checkable (optimisation TSP, min graph colouring). NP-complete = NP-hard ∩ NP.
  • A fast algorithm for any one NP-complete problem ⇒ all of NP is fast ⇒ P = NP (open, unproven). If P ≠ NP, heuristics stay necessary.
  • Prove Z is NP-complete: (1) show Z ∈ NP; (2) reduce a known NP-complete problem to Z.
  • X ∈ P, Y NP-complete: X ∈ NP ✓ · Y ∈ NP ✓ · X → Y ✓ · X NP-complete ✗ (not necessarily) · Y → X would imply P = NP ✗.
  • Reducing X to TSP only shows TSP is at least as hard as X; a fast algorithm for X says nothing about TSP.
  • Advice for an NP-hard problem: exact search (backtracking) for small inputs · greedy / heuristics for large ones · reduce it to a known problem and reuse its solver. Python vs Java does not change the difficulty.
Exam traps
  • Heap: children 2j+1, 2j+2; swap with the smaller child; last parent ⌊n/2⌋−1; BuildHeap O(n).
  • Hash: row = integer % N; probing stops only at a never-used row; deletion needs a marker; chaining λ can exceed 1.
  • BFS marks on enqueue; stack DFS marks on pop. DFS push order: reversed list order (unless told otherwise).
  • Topological sort: reverse the finish order, not the visit order.
  • UCS stops when the goal is dequeued; replace a queued entry only if the new cost is cheaper.
  • TSP totals include the return leg; state your tie-breaks.
  • Greedy ≠ optimal in general; heuristics are fast with no guarantee.
  • NP = “verifiable”, not “not polynomial”; reductions go easier → harder.
